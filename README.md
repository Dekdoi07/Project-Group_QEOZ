## เนื้อหาที่เกี่ยวข้อง
### การกำหนดเส้นทางแบบไดนามิกในเครือข่ายคอมพิวเตอร์
**การกำหนดเส้นทาง (Routing)** คือกระบวนการตัดสินใจที่เราเตอร์ ( _ซึ่งเป็นอุปกรณ์ฮาร์ดแวร์ที่ใช้ในเครือข่ายเพื่อรับและส่งข้อมูลในรูปแบบแพ็กเก็ตบนเครือข่าย_ ) เลือกเส้นทางที่ดีที่สุดในการถ่ายโอนข้อมูลจากต้นทางไปยังปลายทาง เราเตอร์มีอยู่ในเลเยอร์เครือข่ายทั้งในโมเดล OSI และ TCP/IP หน้าที่บางอย่างของเราเตอร์ ได้แก่:

1.  การสร้างเส้นทางที่เหมาะสมที่สุดบนเครือข่ายเพื่อไปยังปลายทาง (ซึ่งมีการกำหนดเส้นทางทั้งแบบคงที่และแบบไดนามิก)
2.  การตัดสินใจเกี่ยวกับการกำหนดเส้นทาง
3.  การปรับสมดุลน้ำหนักบรรทุก



### ประเภทของการกำหนดเส้นทาง
1.  การกำหนดเส้นทางแบบคงที่
2.  การกำหนดเส้นทางเริ่มต้น
3.  การกำหนดเส้นทางแบบไดนามิก

[การกำหนดเส้นทาง](https://www.geeksforgeeks.org/computer-networks/types-of-routing/) แบบคงที่และ แบบเริ่มต้น มีข้อเสียบางประการ จึงได้มีการนำการกำหนดเส้นทางแบบไดนามิกมาใช้
#### **ข้อเสียของการกำหนดเส้นทางแบบคงที่:**

-   การรวมหรือเพิ่มเส้นทางแต่ละเส้นลงในแผนที่การกำหนดเส้นทางด้วยตนเองในเครือข่ายขนาดใหญ่เป็นงานที่ยุ่งยาก
-   การจัดการคำสั่งซื้อนั้นใช้เวลานาน
-   ระบบไม่สามารถเปลี่ยนเส้นทางการรับส่งข้อมูลได้ในกรณีที่ลิงก์บางส่วนล้มเหลว

#### **ข้อเสียของการกำหนดเส้นทางเริ่มต้นคือ:**

-   หากเครือข่ายมีความซับซ้อน การติดตั้งก็จะยากขึ้น

เพื่อเอาชนะข้อบกพร่องของการกำหนดเส้นทางแบบคงที่และแบบเริ่มต้น ในช่วงทศวรรษ 1980 การกำหนดเส้นทางแบบไดนามิกครั้งแรกถูกนำมาใช้ในคอมพิวเตอร์ และโปรโตคอลที่ใช้ในนั้นคือ RIP (routing information protocol)

### การกำหนดเส้นทางแบบไดนามิก

**การกำหนดเส้นทางแบบไดนามิก**เป็นเทคนิคที่ใช้ในการค้นหาเส้นทางที่ดีที่สุดสำหรับการส่งข้อมูลผ่านเครือข่าย โดยในกระบวนการนี้ เราเตอร์สามารถส่งข้อมูลผ่านเส้นทางต่างๆ และไปถึงปลายทางได้ตามสภาพของวงจรการสื่อสารในขณะนั้น

![enter image description here](https://media.geeksforgeeks.org/wp-content/uploads/20211207133356/DynamicRouting.png)
![enter image description here](https://media.geeksforgeeks.org/wp-content/uploads/20211207133356/DynamicRouting.png)

เราเตอร์แบบไดนามิกมีความฉลาดพอที่จะเลือกเส้นทางที่ดีที่สุดสำหรับข้อมูลโดยพิจารณาจากสภาพของสถานการณ์ปัจจุบันในเครือข่าย ณ ขณะนั้น หากส่วนใดส่วนหนึ่งของเครือข่ายล้มเหลวในการส่งข้อมูล เราเตอร์แบบไดนามิกจะใช้อัลกอริธึมของตน (ซึ่งใช้โปรโตคอลการกำหนดเส้นทางเพื่อรวบรวมและแบ่งปันข้อมูลของเส้นทางปัจจุบันระหว่างกัน) และจะเปลี่ยนเส้นทางจากเครือข่ายเดิมไปยังเครือข่ายอื่นแบบเรียลไทม์ ความสามารถและฟังก์ชันการทำงานที่น่าทึ่งนี้ในการเปลี่ยนเส้นทางแบบเรียลไทม์บนเครือข่ายโดยการแบ่งปันสถานะระหว่างกัน คือฟังก์ชันการทำงานหลักของการกำหนดเส้นทางแบบไดนามิก[OSPF](https://www.geeksforgeeks.org/computer-networks/open-shortest-path-first-ospf-protocol-fundamentals/) (Open Shortest Path First) และ[RIP](https://www.geeksforgeeks.org/computer-networks/routing-information-protocol-rip/)เป็นโปรโตคอลบางส่วนที่ใช้สำหรับการกำหนดเส้นทางแบบไดนามิก

ในภาพด้านบน ภาพบนแสดงเส้นทาง_R1->R2->R5->R9->R10_เพื่อส่งข้อมูลจาก**R1** (แหล่งที่มา) ไปยัง**R10** (ปลายทาง) แต่เนื่องจากสาเหตุบางประการ**R9**ไม่สามารถประมวลผลได้ จึงสร้างเส้นทางใหม่ขึ้นมาโดยอัตโนมัติ ซึ่งก็คือ_R1->R2->R5->R8->_ R10

**ประการแรก**โปรโตคอลการกำหนดเส้นทาง ( _โปรโตคอลที่ระบุวิธีการแบ่งปันข้อมูลระหว่างเราเตอร์และการสื่อสารระหว่างกันเพื่อแบ่งปัน/กระจายข้อมูลระหว่างโหนดในเครือข่าย_ ) จะต้องติดตั้งในเราเตอร์แต่ละตัวในเครือข่ายเพื่อให้สามารถแบ่งปันข้อมูลระหว่างกันได้  
**ประการที่สอง**จะเริ่มต้นการทำงานด้วยตนเองโดยไปที่ตารางการกำหนดเส้นทางแรกของเราเตอร์ที่มีข้อมูลเราเตอร์ จากนั้นจะทำงานโดยอัตโนมัติด้วยความช่วยเหลือของอัลกอริทึมการกำหนดเส้นทางแบบไดนามิกและสร้างตารางการกำหนดเส้นทางแบบไดนามิกสำหรับเราเตอร์ที่เหลือในเครือข่าย  
**ประการที่สาม** ข้อมูล การ  กำหนดเส้นทางจะถูกแลกเปลี่ยนระหว่างเราเตอร์ เพื่อในกรณีที่เครือข่ายล่มหรือเราเตอร์ทำงานล้มเหลวและไม่สามารถแบ่งปันข้อมูลกับเราเตอร์ที่เชื่อมต่อได้ ตารางการกำหนดเส้นทางของแต่ละเราเตอร์จะถูกแก้ไขให้ถูกต้องตามสถานการณ์ปัจจุบัน เพื่อให้สามารถส่งข้อมูลไปยังปลายทางได้อย่างต่อ  
**เนื่อง ประการที่สี่**มีโฮสต์เพื่อตรวจสอบหรือจับคู่ที่อยู่เกตเวย์เริ่มต้นกับที่อยู่ IP ของเราเตอร์ในพื้นที่

### การใช้คิวลำดับความสำคัญ

คิวลำดับความสำคัญจะเลือกโหนดที่มีระยะทางปัจจุบันน้อยที่สุดเสมอ เพื่อให้แน่ใจว่าเราจะสำรวจเส้นทางที่สั้นที่สุดก่อนและหลีกเลี่ยงการประมวลผลเส้นทางที่ยาวกว่าโดยไม่จำเป็น อัลกอริทึมของ Dijkstra จะเลือกโหนดที่มีระยะทางน้อยที่สุดก่อนเสมอ ด้วยวิธีนี้ จะทำให้มั่นใจได้ว่าโหนดนั้นได้ตรวจสอบระยะทางที่สั้นที่สุดไปยังเพื่อนบ้านทั้งหมดแล้ว หากโหนดนี้ปรากฏขึ้นอีกครั้งในคิวลำดับความสำคัญในภายหลัง เราไม่จำเป็นต้องประมวลผลซ้ำอีก เนื่องจากเพื่อนบ้านของโหนดนั้นได้ตรวจสอบระยะทางที่น้อยที่สุดที่เป็นไปได้แล้ว

### ขั้นตอนโดยละเอียด:

 -   สร้างอาร์เรย์ระยะทาง dist[] ขนาด V และกำหนดค่าเริ่มต้นให้กับทุกค่าเป็นอนันต์ (∞) เนื่องจากยังไม่ทราบเส้นทางใดๆ
 -   กำหนดระยะห่างของจุดเริ่มต้นเป็น 0 แล้วแทรกเข้าไปในคิวลำดับความสำคัญ
 -   ในขณะที่คิวลำดับความสำคัญยังไม่ว่าง ให้ลบจุดยอดที่มีค่าระยะทางน้อยที่สุดออก
 -   ตรวจสอบ: หากระยะทางที่ดึงออกมามากกว่าระยะทางที่บันทึกไว้สำหรับจุดยอดนี้ (dist[u]) แสดงว่าจุดยอดนี้ได้รับการประมวลผลด้วยระยะทางที่น้อยกว่าแล้ว ดังนั้นให้ข้ามไปและดำเนินการต่อในรอบถัดไป
 -   สำหรับเพื่อนบ้าน v แต่ละตัวของ u ให้ตรวจสอบว่าเส้นทางผ่าน u ให้ระยะทางที่น้อยกว่า dist[v] ปัจจุบันหรือไม่  
    ถ้าใช่ ให้ปรับปรุง dist[v] = dist[u] + น้ำหนักขอบ (d) และเพิ่ม (dist[v], v) ลงในคิวลำดับความสำคัญ
 -   ทำเช่นนี้ต่อไปเรื่อย ๆ จนกว่าคิวลำดับความสำคัญจะว่างเปล่า
 -   เมื่อดำเนินการเสร็จสิ้น อาร์เรย์ dist[] จะมีระยะทางที่สั้นที่สุดจากจุดเริ่มต้นไปยังทุกจุดยอดในกราฟ

    import java.util.ArrayList;
    import java.util.Arrays;
    import java.util.PriorityQueue;
    
    class GFG {
    
        static ArrayList<Integer> dijkstra(ArrayList<ArrayList<int[]>> adj, int src) {
            int V = adj.size();
    
            // Min-heap (priority queue) storing pairs of (distance, node)
            PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    
            // Distance array: stores shortest distance from source
            int[] dist = new int[V];
            Arrays.fill(dist, Integer.MAX_VALUE);
    
            // Distance from source to itself is 0
            dist[src] = 0;
            pq.offer(new int[]{0, src});
    
            // Process the queue until all reachable vertices are finalized
            while (!pq.isEmpty()) {
                int[] top = pq.poll();
                int d = top[0];
                int u = top[1];
    
                // If this distance is not the latest shortest one, skip it
                if (d > dist[u])
                    continue;
    
                // Explore all adjacent vertices
                for (int[] p : adj.get(u)) {
                    int v = p[0];
                    int w = p[1];
    
                    // If we found a shorter path to v through u, update it
                    if (dist[u] + w < dist[v]) {
                        dist[v] = dist[u] + w;
                        pq.offer(new int[]{dist[v], v});
                    }
                }
            }
    
            ArrayList<Integer> result = new ArrayList<>();
            for (int d : dist)
                result.add(d);
    
            // Return the final shortest distances from the source
            return result;
        }
        
        
        static void addEdge(ArrayList<ArrayList<int[]>> adj, int u, int v, int w) {
            adj.get(u).add(new int[]{v, w});
            adj.get(v).add(new int[]{u, w});
        }
    
        public static void main(String[] args) {
            int V = 5;
            int src = 0;
    
            ArrayList<ArrayList<int[]>> adj = new ArrayList<>();
            for (int i = 0; i < V; i++) {
                adj.add(new ArrayList<>());
            }
    
            addEdge(adj, 0, 1, 4);
            addEdge(adj, 0, 2, 8);
            addEdge(adj, 1, 4, 6);
            addEdge(adj, 1, 2, 3);
            addEdge(adj, 2, 3, 2);
            addEdge(adj, 3, 4, 10);
    
            ArrayList<Integer> result = dijkstra(adj, src);
            for (int d : result)
                System.out.print(d + " ");
            System.out.println();
        }
    }

สมมติว่ามีขอบที่มีน้ำหนักติดลบ หลังจากที่ Dijkstra กำหนดให้จุดยอด u เป็นค่าสุดท้ายแล้ว อาจมีเส้นทางอื่นผ่านจุดยอด v บางจุด (ซึ่งจะประมวลผลในภายหลัง) ที่นำกลับไปยัง u ด้วยระยะทางรวมที่สั้นกว่าเนื่องจากขอบที่มีน้ำหนักติดลบ ดังนั้น สมมติฐานก่อนหน้านี้ของอัลกอริทึมที่ว่า dist[u] เป็นค่าสุดท้ายจึงไม่ถูกต้องอีกต่อไป

### เรียนรู้เรื่องฐานข้อมูล

การเรียนรู้เกี่ยวกับฐานข้อมูลเป็นสิ่งสำคัญในยุคดิจิทัลที่ทุกสิ่งทุกอย่างถูกเชื่อมต่อเข้าด้วยกันผ่านข้อมูลมากมายในปัจจุบัน เรารู้จักกันดีว่าฐานข้อมูลเป็นระบบที่ช่วยในการจัดเก็บและจัดการข้อมูล แต่หากพูดถึง "Spatial Databases" หรือฐานข้อมูลเชิงพื้นที่แล้ว หลายคนอาจจะยังไม่คุ้นเคยเท่าไรนัก ในบทความนี้ เราจะมาเจาะลึกเกี่ยวกับสิ่งที่ทำให้ Spatial Databases มีความพิเศษ และดูว่าจะนำไปประยุกต์ใช้ในสถานการณ์จริงได้อย่างไร

#### Spatial Database คืออะไร?

Spatial Databases เป็นฐานข้อมูลที่พัฒนาขึ้นเพื่อจัดเก็บข้อมูลเกี่ยวกับตำแหน่งเชิงพื้นที่ ซึ่งอาจรวมเอาแง่มุมต่างๆ เช่น พิกัดทางภูมิศาสตร์ รูปร่าง ขนาด และความสัมพันธ์ระหว่างข้อมูลเชิงพื้นที่เหล่านี้เข้าด้วยกัน Spatial Databases ถูกออกแบบมาเพื่อรองรับการทำงานที่สัมพันธ์กับแผนที่หรือข้อมูลที่มีการอ้างอิงตำแหน่งการใช้งาน เช่น คลังข้อมูลทางภูมิศาสตร์ ระบบข้อมูลการนำทาง การทำการตลาดเฉพาะพื้นที่ และอื่นๆ อีกมากมาย

#### การใช้งาน Spatial Database

หนึ่งในคุณสมบัติที่โดดเด่นของ Spatial Databases คือความสามารถในการจัดการข้อมูลที่ประกอบด้วยมิติหลายอย่าง ลองพิจารณาการใช้งานบางส่วนดังต่อไปนี้

1. **ระบบนำทาง (Navigation Systems):** ระบบนำทาง เช่นที่สามารถพบได้ใน Google Maps พึ่งพา Spatial Databases อย่างหนัก ข้อมูลเกี่ยวกับเส้นทาง สถานที่ตั้ง และสถานที่ท่องเที่ยวถูกจัดเก็บในรูปแบบฐานข้อมูลเชิงพื้นที่ ซึ่งทำให้การคำนวณระยะทางและการแนะนำเส้นทางที่รวดเร็วและแม่นยำเป็นไปได้

2. **การวิเคราะห์พื้นที่สำหรับเกษตรกรรม (Agricultural Land Analysis):** การใช้ Spatial Databases กับข้อมูลดาวเทียมหรือโดรน สามารถช่วยในการตรวจสอบสภาพพื้นดิน การเจริญเติบโตของพืช และการจัดการทรัพยากรอย่างมีประสิทธิภาพ

3. **การจัดการสาธารณูปโภค (Utility Management):** การจัดการสาธารณูปโภคต่างๆ เช่น การจ่ายน้ำหรือไฟฟ้า สามารถทำได้อย่างมีประสิทธิภาพยิ่งขึ้นโดยการใช้ Spatial Databases ในการติดตามตำแหน่งของสายไฟหรือท่อใต้ดิน ซึ่งช่วยในการดูแลรักษาและจัดการความเสี่ยงที่เป็นไปได้

#### ตัวอย่างโค้ดการใช้งาน Spatial Database

ในที่นี้เราจะนำเสนอการใช้งาน PostgreSQL ร่วมกับ PostGIS ซึ่งเป็นส่วนเสริมที่ช่วยในการจัดการข้อมูลเชิงพื้นที่

```sql

-- ติดตั้งส่วนเสริม PostGIS
CREATE EXTENSION postgis;

-- การสร้างตารางเพื่อเก็บข้อมูลเมืองพร้อมกับจุดศูนย์กลาง
CREATE TABLE cities (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    location GEOGRAPHY(Point)
);

-- การเพิ่มข้อมูลเมือง
INSERT INTO cities (name, location)
VALUES
('Bangkok', ST_GeographyFromText('SRID=4326;POINT(100.5018 13.7563)')),
('Chiang Mai', ST_GeographyFromText('SRID=4326;POINT(98.9757 18.7883)'));

-- การค้นหาเมืองที่อยู่ภายในระยะ 500 กิโลเมตรจากจุดที่ให้
SELECT name
FROM cities
WHERE ST_DWithin(location, ST_GeographyFromText('SRID=4326;POINT(100.5018 13.7563)'), 500000);

```

ในตัวอย่างโค้ดข้างต้น เราได้สร้างตารางสำหรับเก็บข้อมูลเมืองที่มีการรวมตำแหน่งพิกัดเชิงภูมิศาสตร์ และได้เพิ่มข้อมูลพร้อมกับทำการค้นหาด้วยฟังก์ชัน `ST_DWithin` ซึ่งช่วยในการคำนวณว่ามีตำแหน่งที่อยู่ภายในระยะที่กำหนดหรือไม่

#### ข้อพิจารณาในการเลือกใช้ Spatial Databases

การเลือกใช้ Spatial Databases นั้นไม่เพียงแต่ต้องพิจารณาถึงความสามารถในการจัดเก็บและประมวลผลข้อมูลเชิงพื้นที่ แต่ยังต้องคำนึงถึงประสิทธิภาพและการรองรับของระบบด้วย เห็นได้ชัดว่าในยุคที่ข้อมูลมีความซับซ้อนและปริมาณมาก การเลือกใช้เทคโนโลยีที่เหมาะสมจะช่วยให้ธุรกิจหรือการวิจัยบรรลุเป้าหมายได้อย่างมีประสิทธิผลมากขึ้น

สรุปแล้ว การมีความรู้เกี่ยวกับ Spatial Databases จะเป็นประโยชน์อย่างมาก ไม่ว่าจะใช้ในการพัฒนาทักษะด้านเทคโนโลยีสารสนเทศหรือนำไปประยุกต์ในภาคส่วนต่างๆ จึงเป็นการศึกษาที่ควรถูกพัฒนาต่อไปอย่างต่อเนื่องเพื่อก้าวทันความต้องการที่เพิ่มขึ้นในโลกปัจจุบัน

## คำแนะนำจาก Gemini
สำหรับการทำโปรเจกต์ระดับ Computer Science ที่มีความซับซ้อนทั้งฝั่ง Data และ Routing การสืบค้นงานวิจัยเพื่อนำมาเป็น Reference ควรครอบคลุมหัวข้อหลักๆ ดังต่อไปนี้ครับ

**1. อัลกอริทึมการค้นหาเส้นทางแบบพลวัต (Dynamic Pathfinding Algorithms & Graph Theory)** 
เนื่องจากในสถานการณ์ภัยพิบัติ เส้นทางปกติอาจถูกตัดขาด ระบบจำเป็นต้องคำนวณเส้นทางใหม่ทันที งานวิจัยในกลุ่มนี้จะช่วยให้ระบบแผนที่ของคุณฉลาดขึ้น

-   **Keywords:** Dynamic Routing Algorithm, Real-time Pathfinding in Disaster, Modified Dijkstra's Algorithm, A* Algorithm for obstacle avoidance, Dynamic Graph Weighting.
    
-   **สิ่งที่ควรหา:** วิธีการปรับค่าน้ำหนัก (Weight) ของเส้นทาง (Edge) ในกราฟแบบเรียลไทม์เมื่อเกิดน้ำท่วมหรือไฟไหม้ เพื่อให้อัลกอริทึมอย่าง Dijkstra หรือ A* สามารถหาเส้นทางที่สั้นและปลอดภัยที่สุดเส้นใหม่ได้ทันทีโดยไม่ต้องคำนวณกราฟใหม่ทั้งหมด
    

**2. ระบบสารสนเทศภูมิศาสตร์และการจัดเก็บข้อมูลเชิงพื้นที่ (GIS & Spatial Data Management)** การสร้างแผนที่ที่สามารถระบุตำแหน่งจุดเกิดเหตุและพิกัดผู้ป่วย ต้องใช้โครงสร้างฐานข้อมูลที่รองรับข้อมูลเชิงพื้นที่ (Spatial Data)

-   **Keywords:** Web GIS, Spatial Database, PostGIS, OpenStreetMap (OSM) integration, Spatial Indexing.
    
-   **สิ่งที่ควรหา:** สถาปัตยกรรมการออกแบบฐานข้อมูลเพื่อเก็บพิกัด (Latitude/Longitude) ของผู้ป่วยติดเตียง และเทคนิคการ Query ข้อมูลเพื่อหาผู้ป่วยที่อยู่ในรัศมีของพื้นที่เสี่ยงภัยได้อย่างรวดเร็ว
    

**3. การอพยพและโลจิสติกส์สำหรับกลุ่มเปราะบาง (Evacuation Logistics for Vulnerable Populations)** การช่วยเหลือผู้ป่วยติดเตียงมีเงื่อนไขที่ซับซ้อนกว่าคนปกติ เช่น ต้องใช้รถพยาบาลเฉพาะทาง งานวิจัยกลุ่มนี้จะช่วยในเรื่องการจัดลำดับความสำคัญและการบริหารทรัพยากรรถกู้ภัย

-   **Keywords:** Healthcare logistics in emergencies, Evacuation routing for bedridden patients, Vulnerable population spatial analysis, Vehicle Routing Problem (VRP) in disaster.
    
-   **สิ่งที่ควรหา:** โมเดลทางคณิตศาสตร์หรืออัลกอริทึมที่ใช้จัดสรรรถกู้ภัยให้เดินทางไปรับผู้ป่วยหลายๆ จุดในเส้นทางเดียวกันได้อย่างมีประสิทธิภาพสูงสุด
    

**4. การผสานข้อมูลภัยพิบัติแบบเรียลไทม์ (Real-time Crisis Situational Awareness)** การทำให้แผนที่รู้ว่าตรงไหนมีภัยพิบัติ ต้องมีการรับส่งและประมวลผลข้อมูลตลอดเวลา

-   **Keywords:** Real-time disaster mapping, Dynamic risk mapping, Crowdsourcing data in disaster management.
    
-   **สิ่งที่ควรหา:** รูปแบบการรับข้อมูลสภาวะวิกฤต (เช่น ระดับน้ำหลาก หรือทิศทางลมในเหตุไฟไหม้) เพื่อนำมาสร้างเป็นพื้นที่รูปปิด (Polygon) บนแผนที่ และกำหนดให้ระบบนำทางหลีกเลี่ยงพื้นที่เหล่านั้น
    

**5. เครือข่ายการสื่อสารและการส่งข้อมูลพิกัดในภาวะวิกฤต (Emergency Communication & Telemetry)** ในสถานการณ์ภัยพิบัติรุนแรง สัญญาณอินเทอร์เน็ตมือถือมักจะล่ม การออกแบบให้ระบบนำทางหรือพิกัดผู้ป่วยสามารถส่งข้อมูลผ่านช่องทางสำรองได้จะทำให้โปรเจกต์มีความสมบูรณ์แบบมากยิ่งขึ้นสำหรับหน่วยกู้ภัย

-   **Keywords:** Resilient communication networks, Radio-over-IP (RoIP) in disaster management, Low-bandwidth spatial data transmission, Emergency vehicle telemetry.
    
-   **สิ่งที่ควรหา:** สถาปัตยกรรมการส่งข้อมูลพิกัดละติจูด/ลองจิจูดขนาดเล็ก หรือสเตตัสการอพยพ ผ่านระบบเครือข่ายวิทยุสื่อสาร หรือระบบ Telemetry กลับมายังศูนย์สั่งการ เมื่อระบบเซลลูลาร์ปกติไม่สามารถใช้งานได้
